# 双语界面与 Pages CMS 最小改动设计

## 目标

在保留 Astrofy 现有路由和 Markdown 内容集合的前提下，为网站增加默认中文、可切换英文的界面，并通过 Pages CMS 编辑网站基础设置、静态页面内容、博客和商店内容。

本设计解决两个问题：

1. 非程序员可以在 Pages CMS 中编辑网站，而不需要直接修改 Astro 文件。
2. 网站的导航、按钮、首页、项目、服务、CV、页脚等界面内容支持中文和英文；博客与商店条目仍然只保存一份，正文使用作者实际写入的语言。

## 现状与约束

- 项目使用 Astro 4.11.0，采用静态构建。
- 首页、项目、服务、CV、404 等页面的文字直接写在 `.astro` 文件中。
- 博客位于 `src/content/blog/*.md`，商店位于 `src/content/store/*.md`，由 Astro 内容集合读取。
- 当前 URL 为 `/`、`/projects`、`/blog/[slug]` 等，没有国际化路由。
- 语言切换器放在页面右上角，默认语言为中文。
- 用户要求尽量少改动原项目，不重构路由，不要求文章成对翻译。
- 不修改 Cloudflare Pages、CI/CD 或部署配置。
- 不升级现有依赖，也不引入完整国际化框架。

## 方案比较

### 方案一：完整 `/zh/`、`/en/` 路由

每个页面生成中文和英文两个 URL，搜索引擎支持最好，但需要重写所有页面路径、内部链接、分页、标签页、站点地图和文章路由。相对于当前需求，改动范围过大。

### 方案二：所有内容都保存中英文版本

每篇博客、商品和静态页面都维护两份内容，翻译关系清楚，但编辑成本高，而且不符合“文章写什么语言就显示什么语言”的要求。

### 方案三：保留 URL，仅切换界面语言

静态页面和固定界面文字提供中英文版本；博客和商店条目继续使用当前单份 Markdown 文件。语言选择保存在浏览器中，所有现有 URL 保持不变。

采用方案三。它与原项目结构最接近，改动集中在内容数据、布局和界面文字，不影响文章生成方式。

## 总体架构

### 1. Pages CMS 配置

在仓库根目录增加 `.pages.yml`，配置三类编辑入口：

- 网站与静态页面设置：编辑结构化 JSON 数据中的中文和英文字段。
- 博客：继续编辑 `src/content/blog/*.md`，字段与现有 `blogSchema` 对齐。
- 商店：继续编辑 `src/content/store/*.md`，字段与现有 `storeSchema` 对齐。

媒体文件统一上传到 `public/uploads`，内容中保存为 `/uploads/<filename>`。现有 `public` 图片继续可用，不迁移、不删除。

### 2. 网站数据

新增 `src/data/site-settings.json`，作为 Pages CMS 中的“网站设置”。数据分为三部分：

- `shared`：姓名、头像、邮箱、社交链接等不需要翻译的值。
- `zh`：中文网站标题、简介、首页介绍、按钮、菜单、栏目标题、页脚和提示文字。
- `en`：与 `zh` 字段结构完全一致的英文内容。

静态页面中现有的项目、服务和 CV 示例数据也移入该文件对应的中英文区域，使其可以通过 CMS 编辑。页面布局和组件样式保持不变。

为了避免设置页失控，不把博客正文、商店正文或图片二进制数据放入该 JSON 文件。

### 3. 语言状态

新增一个轻量语言模块，语言值只允许：

- `zh`：默认值，对应 `zh-CN`。
- `en`：对应 `en`。

首次访问使用中文。用户切换后，把选择保存到浏览器 `localStorage` 的 `site-language` 键中。后续刷新和页面跳转继续使用该语言。

项目已启用 Astro View Transitions，因此每次 `astro:page-load` 事件触发时都要重新应用已保存的语言，避免跳转后恢复中文。

### 4. 界面渲染

新增一个职责单一的本地化文本组件。组件接收 `zh` 和 `en` 两个值，并根据 `<html data-language>` 显示其中一个。页面继续由 Astro 静态生成，不增加服务器运行时。

在页面 `<head>` 尽早读取已保存语言并设置 `data-language`，减少英文用户刷新时先看到中文的闪烁。切换时同步更新：

- `<html lang>`；
- `<html data-language>`；
- 语言按钮的选中状态和无障碍属性；
- 页面标题和描述等可切换的基础元数据。

语言切换组件挂在公共布局中，并固定显示在右上角，因此桌面端和移动端都可使用。它不修改 URL。

## 页面与内容行为

### 静态页面

以下页面的基础文字和列表内容从 `site-settings.json` 读取，并随界面语言切换：

- 首页；
- 项目；
- 服务；
- CV；
- 404；
- 导航、页脚和通用按钮。

页面现有布局、卡片组件和响应式样式不重新设计。

### 博客

- 保持现有 `src/content/blog/*.md` 文件结构和 `blogSchema`。
- 每篇文章只有一个标题、简介和正文。
- 中文文章显示中文，英文文章显示英文，不自动翻译，不要求配对。
- `/blog`、标签分页和 `/blog/[slug]` 地址保持不变。
- 语言切换只改变导航、分页按钮、空状态和“最后更新”等外围界面文字；文章标题、简介、标签和正文不变。
- 不增加文章语言字段，不按语言筛选文章。

### 商店

- 保持现有 `src/content/store/*.md` 文件结构和 `storeSchema`。
- 商品标题、简介和正文保持作者写入的语言。
- 语言切换只影响“购买”“上一页”“下一页”等外围界面文字。
- 商品 URL 保持不变。

### RSS 与站点地图

RSS 和站点地图继续使用现有单一内容源和 URL，不为语言生成副本。RSS 的站点标题和简介使用默认中文设置，文章内容保持原样。

## 数据流

1. 用户在 Pages CMS 中编辑网站设置或 Markdown 内容。
2. Pages CMS 将变更保存到 GitHub 仓库。
3. Cloudflare Pages 按现有流程运行 `pnpm run build`。
4. Astro 在构建时读取 `site-settings.json`、博客集合和商店集合，生成静态页面。
5. 浏览器首次显示中文界面；用户在右上角选择英文后，界面立即切换并保存偏好。
6. 博客和商品正文始终原样显示，不参与语言切换。

## 校验与错误处理

- `.pages.yml` 将必要字段设为必填，减少缺失配置。
- 为 `site-settings.json` 建立本地类型和结构校验；中文与英文字段结构不一致时，构建失败并指出字段路径。
- 可选链接或图片为空时，页面隐藏对应按钮或图片，而不是生成无效元素。
- 语言存储值不是 `zh` 或 `en` 时自动回退到 `zh`。
- 浏览器禁用或限制 `localStorage` 时，本次切换仍可工作，但刷新后回到中文。
- CMS 保存格式错误时由本地构建和 Cloudflare 构建拦截，不通过绕过校验来发布。

## 验证标准

### 自动验证

- `pnpm run build` 成功。
- Astro 内容集合校验通过。
- 现有博客、标签、分页、商店和 RSS 路径仍能生成。
- 不新增依赖，不改变 Cloudflare 构建配置。

### 浏览器验证

- 首次访问默认显示中文。
- 右上角可以切换中英文。
- 刷新页面后语言选择保持。
- 使用站内链接和 View Transitions 跳转后语言选择保持。
- 桌面端和移动端均可看到并操作语言切换器。
- 首页、项目、服务、CV、404、导航、页脚及通用按钮同步切换。
- 博客和商品的标题、简介与正文在切换时不改变。
- 中文和英文设置均可在 Pages CMS 中打开、修改并保存。
- 新建博客文章后只生成一个 Markdown 文件和一个文章 URL。

## 明确不包含的范围

- 不建立 `/zh/`、`/en/` 路由。
- 不自动翻译内容。
- 不为文章或商品创建双语副本。
- 不增加文章语言筛选或语言标签。
- 不重新设计页面视觉样式。
- 不删除现有示例文章、商品或图片；它们由用户之后通过 CMS 替换。
- 不修改部署、域名、环境变量或 CI/CD 配置。

## 交付边界

本功能完成后，用户可通过 Pages CMS 编辑网站设置、静态页面、博客和商店内容；网站默认中文，右上角可切换英文；原有文章、商品和 URL 结构保持不变。提交和版本标签可在本地完成，但任何 `git push` 仍需用户单独明确授权。
